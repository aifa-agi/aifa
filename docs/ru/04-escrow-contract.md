# 4. Архитектура смарт-контракта: A2AEscrow.sol (Эскроу, EIP-712, Time-Lock)

Смарт-контракт A2AEscrow.sol — это финансовое ядро протокола AIFA Network. Его главная задача — гарантировать (Trustless Guarantee), что Исполнитель получит оплату за потраченные вычислительные ресурсы, а Заказчик не сможет украсть результат без оплаты. Поскольку запись гигабайтов данных в блокчейн стоит миллионы долларов, эскроу-контракт оперирует исключительно легковесными криптографическими хэшами и подписями, оставляя сами AI-запросы (Payload) в P2P-сети.

## 4.1 Конечный автомат (State Machine) жизненного цикла задачи

Логика эскроу реализована как строгий конечный автомат. Каждая задача (Task) в контракте представляет собой структуру данных, занимающую ровно один 256-битный слот памяти (Storage Slot) для максимальной экономии газа (Bit-packing).

В Solidity это описывается следующим образом:

```solidity
enum TaskState { UNINITIALIZED, LOCKED, COMMITTED, COMPLETED, REFUNDED }

struct Task {
    uint96 amount;        // Оплата в USDC (до $79 млрд, достаточно 96 бит)
    uint40 lockedAt;      // Таймстемп создания (до 34841 года)
    uint40 commitTime;    // Таймстемп отправки результата Исполнителем
    address provider;     // 160 бит - Ethereum-адрес Исполнителя
    TaskState state;      // 8 бит - Текущий статус
}
```

Жизненный цикл:

LOCKED: Заказчик инициирует транзакцию, блокируя USDC на контракте. Указывается точный адрес provider, который имеет право выполнить задачу. Никто другой не может перехватить этот заказ.

COMMITTED: Исполнитель завершил ML-инференс, отправил результат по P2P-сети и зафиксировал в контракте факт отправки (запустил таймер).

COMPLETED: Задача успешно закрыта, USDC переведены Исполнителю, а комиссия протокола ушла в Paymaster.

REFUNDED: Исполнитель отклонил задачу (например, сработал локальный A2A Shield) или истек таймаут принятия заказа, средства возвращены Заказчику.

## 4.2 Криптографические квитанции (Execution Witness по EIP-712)

Чтобы закрыть задачу и забрать деньги из контракта, Исполнитель вызывает функцию executeTask(). Но смарт-контракт слеп — он не знает, действительно ли Исполнитель сгенерировал нейросетью нужный текст или видео.

Для доказательства используется стандарт EIP-712 (Typed Data Hashing and Signing).

Оффчейн-подпись: Когда Заказчик получает результат по P2P-каналу (через Envoy Proxy), его локальный агент проверяет данные. Если все корректно, агент Заказчика своим приватным ключом подписывает специальный JSON-объект (Квитанцию):
{ "taskId": 12345, "resultHash": "0xabc...", "amount": 5000000 }.

Ончейн-исполнение: Исполнитель берет эту цифровую подпись Заказчика (массив байтов v, r, s) и отправляет её в смарт-контракт.

Верификация (ecrecover): Контракт A2AEscrow.sol восстанавливает публичный адрес из подписи. Если этот адрес совпадает с адресом Заказчика, заказавшим taskId = 12345, смарт-контракт немедленно переводит USDC на баланс Исполнителя.

## 4.3 Time-Lock: Механизм защиты от зависания (Anti-Griefing)

Это реализация «лекарства», которое мы обсуждали на этапе аудита. Что делать, если Заказчик получил результат по P2P, но специально отключился и не прислал EIP-712 подпись, чтобы заморозить деньги Исполнителя?

В контракт встроена функция защиты claimTimeout(uint256 taskId).

Commitment Phase: Как только Исполнитель завершил работу, он вызывает дешевую функцию commitResult(taskId, resultHash), которая переводит задачу в статус COMMITTED и записывает текущее время commitTime = block.timestamp.

Challenge Window: У Заказчика есть строго заданное окно (например, DISPUTE_PERIOD = 5 минут), чтобы прислать подпись.

Auto-Claim (Авто-разблокировка): Если Заказчик молчит, а 5 минут прошли, Исполнитель вызывает claimTimeout(taskId). Контракт проверяет: block.timestamp > commitTime + DISPUTE_PERIOD. Если условие верно, контракт принудительно закрывает задачу и переводит деньги Исполнителю без подписи Заказчика.

Эта логика делает финансовый троллинг математически невозможным. Исполнитель всегда защищен.

## 4.4 Расщепление платежей (Fee Split & Routing)

В момент перехода задачи в статус COMPLETED, контракт A2AEscrow.sol не просто переводит 100% средств Исполнителю, он выступает в роли автоматического бухгалтера (Splitter):

Provider Share (Например, 98%): Основная оплата за вычисления отправляется на кошелек Исполнителя.

Relay Fee (Например, 0.5%): Если трафик шел через TURN-мост (из-за NAT), контракт считывает адрес Relay-узла и отправляет ему микро-компенсацию за пропускную способность.

Protocol Fee / Burn (Например, 1.5%): Остаток направляется на адрес контракта Paymaster для последующей пакетной конвертации в $AIFA и автоматического сжигания (реализация скрытого Proof-of-Burn).

Благодаря жесткой оптимизации (Bit-packing) и использованию EIP-712 подписей вместо хранения строк, исполнение этого контракта в L2 сетях (Arbitrum / Base) будет стоить сотые доли цента, что критически важно для микротранзакций ИИ-агентов.
