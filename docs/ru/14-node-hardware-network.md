# 14. Node Operator Guide: Спецификации оборудования и сетевой инфраструктуры

Устойчивость, пропускная способность и задержки (latency) сети AIFA Network напрямую зависят от конфигурации оборудования, на котором разворачиваются Супер-Узлы (Core Relays) и TURN-мосты. Поскольку узлы выполняют функции P2P-маршрутизации Kademlia DHT, обслуживания TLS-сессий (Envoy) и проксирования зашифрованного E2EE-трафика для клиентов за Symmetric NAT, требования к железу и сетевому каналу жестко детерминированы.

В этом разделе описаны официальные аппаратные профили для операторов, желающих вносить гарантийный стейк и получать комиссии за пропускную способность (Relay Gas Fee).

## 14.1 Градация профилей узлов (Node Tier Profiles)

Протокол разделяет инфраструктурные серверы на три категории в зависимости от выполняемых ролей в сети:

| Профиль узла | Назначение и Роль | Мин. Стейк ($AIFA) | Целевая нагрузка |
|---|---|---|---|
| Tier-1: Discovery Node | Обслуживание Kademlia DHT, хранение таблиц k-buckets, поиск адресов и подписей агентов. | $1,000$ $AIFA | Низкий трафик, высокочастотные UDP-запросы. |
| Tier-2: Super-Relay Node | DHT + Обслуживание TURN-мостов, проксирование E2EE-трафика, проведение UDP Hole Punching. | $5,000$ $AIFA | Высокий трафик, параллельные mTLS-сессии, высокая нагрузка на I/O. |
| Tier-3: Enterprise Bundler & Relay | Полный стек: DHT + TURN + Bundler (ERC-4337) + Локальная L2 Full Node (Arbitrum/Base). | $25,000$ $AIFA | Максимальный приоритет в маршрутизации, проведение UserOps в приватные RPC. |

## 14.2 Минимальные и Рекомендуемые системные требования

Для обеспечения нулевого процента сброса пакетов и прохождения регулярных проверок аптайма (PING) со стороны соседних узлов, сервера операторов должны соответствовать следующим аппаратным спецификациям:

**Tier-2: Super-Relay Node (Стандартный профиль оператора)**

CPU: 8 vCPU (x86-64 v3 / AMD EPYC или Intel Xeon) с аппаратной поддержкой инструкций AES-NI (критически важно для мгновенного TLS-рукопожатия в Envoy).

RAM: 16 GB ECC RAM (использование ECC-памяти рекомендуется для предотвращения спонтанных битовых сбоев, вызывающих расхождение криптографических подписей).

Storage: 500 GB NVMe SSD (PCIe Gen4, minimum 3000 MB/s Read/Write). Дисковая система используется для кэширования таблиц маршрутизации, временных буферов Envoy и логов Prometheus.

Network Bandwidth: Dedicated 1 Gbps Unmetered (Simplex/Duplex). Пропускная способность — главный ресурс узла. Серверы с лимитированным трафиком (Metered) категорически не рекомендуются.

Public IPv4/IPv6: Обязательно наличие статичного статического публичного IPv4 адреса (без CGNAT) и подсети IPv6 (/64).

**Tier-3: Enterprise Bundler & Relay (Профессиональный валидатор)**

CPU: 16–32 vCPU (AMD EPYC 7003/9004 series или Ampere Altra MAX ARM64).

RAM: 64 GB – 128 GB DDR5.

Storage: 2 TB NVMe SSD (Enterprise Grade: DWPD $\ge 1$).

Network Bandwidth: 10 Gbps Uplink (с гарантированной полосой не менее 2 Gbps).

## 14.3 Сетевая конфигурация и брандмауэр (Port Matrix)

Оператор обязан открыть на внешнем файрволе (AWS Security Groups / Hetzner Firewall / UFW) следующие сетевые порты для правильного функционирования p2p-стека:

```
                  ┌─────────────────────────────────────────┐
                  │          СЕТЕВОЙ ЭКРАН (UFW)            │
                  └─────────────────────────────────────────┘
                                       │
        ┌──────────────────────────────┼──────────────────────────────┐
        │                              │                              │
        ▼                              ▼                              ▼
  [Port 4001 UDP]               [Port 443 TCP]              [Port 3478 UDP/TCP]
 Kademlia DHT Discovery         Envoy mTLS Data Plane          STUN/TURN NAT Traversal
 (P2P Поиск адресов)            (Зашифрованный трафик)         (Пробивка брандмауэров)
```

| Порт | Протокол | Направление | Назначение в архитектуре AIFA Network |
|---|---|---|---|
| 4001 | UDP | Inbound/Outbound | Kademlia DHT Engine: Поиск узлов, обмен PING/STORE сообщениями. |
| 443 | TCP | Inbound/Outbound | Envoy mTLS Data Plane: Проксирование зашифрованного полезного груза (Payload). |
| 3478 | UDP/TCP | Inbound/Outbound | STUN/TURN Service: Определение публичных IP и создание Relay-мостов. |
| 9090 | TCP | Localhost Only | Prometheus Metrics: Локальный мониторинг состояния ноды (Закрыт извне!). |

## 14.4 Географическое распределение и Latency SLA

Для минимизации задержек при передаче пакетов между ИИ-агентами сеть распределяет награды (Relay Gas Fee) с учетом геолокации узла:

Топологический приоритет: Алгоритм Kademlia при поиске TURN-моста выбирает ноду с наименьшим RTT (Round Trip Time) до Заказчика и Исполнителя.

SLA по задержкам (Latency Thresholds):
- Внутрирегиональный трафик (EU-EU, US-US): RTT $< 30$ мс.
- Трансконтинентальный трафик (EU-US, ASIA-EU): RTT $< 120$ мс.

Рекомендации по хостингу: Для обеспечения максимальной связности рекомендуется разворачивать Супер-Узлы в ключевых сетевых хабах: Франкфурт (FRA), Ашберн (IAD), Токио (TYO), Сингапур (SIN) в дата-центрах уровня Tier-III+ (Equinix, Hetzner, OVHcloud, AWS).
